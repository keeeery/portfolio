# /portfolio-image-crop — 원본 스크린샷 → 4:3 크롭 → 기술 문서 반영

대상: `src/$ARGUMENTS/` (비어 있으면 `_raw/`에 파일이 있는 프로젝트를 보여 주고 고르게 함)

> 직접 만든 스킬입니다(템플릿에 없음). `/portfolio-update`가 스킬 폴더를 템플릿으로 바꾸면 사라질 수 있습니다.

`CLAUDE.md`의 **반드시 지킬 원칙**을 따릅니다. 특히:
- **원본은 건드리지 않습니다.** `_raw/`의 파일은 읽기만 하고, 크롭은 `images/`에 새 파일로 씁니다.
- **확인받기 전에는 기술 문서·data를 고치지 않습니다.** 크롭 → 보여 주기 → 요청 반영을 사용자가 "반영해 줘"라고 할 때까지 반복합니다.
- 그림 설명(alt)은 **화면에 보이는 것만** 씁니다(지어내지 않기). 새로 쓴 설명은 마무리 보고에서 확인을 부탁합니다.

## 폴더

```
src/<폴더>/
├── _raw/              # 원본 스크린샷 (git 제외, 빌드가 읽지 않음) — 사용자가 넣음
│   └── crops.json     # 이 스킬의 기록: 크롭 파일 → 원본·자른 범위 (다시 다듬을 때 씀)
├── images/            # 크롭 결과 (기술 문서가 가리킴, git에 올라감)
└── <기술 문서>.md
```

도구(이 폴더): `measure.py`(픽셀 위치 재기), `crop.py`(4:3 자르기, macOS `sips`). 둘 다 `python3 -I`로 실행합니다.

## 크롭 기준

| 항목 | 기준 |
|---|---|
| 비율 | **4:3** (포트폴리오 문서의 그림 칸이 4:3 고정·꽉 채움). `crop.py`가 맞춰 줌 |
| GIF | 쓰지 않음. 움직임은 정지 화면 한 프레임 + 시연 영상으로 대신 |
| 담을 것 | 그 절이 설명하는 부분이 칸을 채우게. 설명에 필요한 UI(타이머·카드 슬롯 등)만 남기고 나머지 HUD는 뺌 |
| 가장자리 | 카드·UI·글자가 **반쯤 걸린 조각**이 없게. 걸리면 범위를 몇 px 옮기거나 그 물체를 다 담음 |
| 정렬 요청 | "가운데로·대칭·여백 맞추기"는 눈대중 대신 `measure.py bbox`로 기준 물체의 위치를 재서 계산 |
| 해상도 | 키우지 않음. 결과 폭이 600px보다 작으면 "발표 덱에서는 작게 보일 수 있음"을 알림 |
| 대표 이미지 | 플레이 화면 4:3. 로고가 있으면 로고는 자르지 않고(투명 PNG 그대로) 플레이 화면 위에 겹침(`coverLogo`) — 로고가 위쪽 1/3에 오므로 **위쪽이 비어 있는 장면**이 좋음 |
| 파일 이름 | 내용을 나타내는 소문자-하이픈(`path-border.png`, `boss-laser.png`). 원본과 같은 이름이면 `-crop`을 붙임. `images/`의 다른 파일을 덮어쓰지 않음(이 스킬이 만든 크롭은 다시 다듬을 때 덮어씀) |

## 1. 원본과 문서 읽기

1. `src/<폴더>/_raw/`의 이미지(`.png .jpg .jpeg`)를 나열하고 `_raw/crops.json`이 있으면 읽습니다. 이미 크롭이 있고 기술 문서에 쓰인 원본은 "반영됨"으로 따로 표시하고, 사용자가 다시 다듬자고 할 때만 다룹니다.
2. 기술 문서를 끝까지 읽고 `#`~`###` 제목, 이미 있는 그림 줄(`![...](images/...)`), 표 위치를 파악합니다. `data/projects/<폴더>.json`이 있으면 `highlights[].section`(포트폴리오 문서의 기능 소개 절)과 `cover`·`coverLogo`를 확인합니다.
3. 원본을 하나씩 **직접 봅니다**(Read). 무엇이 보이는 장면인지 한 줄로 적습니다.

## 2. 자리 정하기와 초안 크롭

1. 원본마다 넣을 절을 정합니다.
   - 대표 이미지: 개요 첫 절(보통 `1.1 What`)의 맨 위. 로고가 있으면 로고 줄 다음 줄에 플레이 화면.
   - 기능 화면: `highlights[].section` 절 **안**(다음 `###` 전, 표 밖) — 포트폴리오 문서는 그 절 안의 첫 그림만 가져갑니다.
   - 그 밖: 그 장면을 설명하는 문단이 있는 절, 그 문단 바로 아래.
   - 어울리는 절이 없으면 억지로 넣지 않고 표에 "넣을 곳 없음"으로 적어 사용자에게 묻습니다.
2. 범위를 정하고 자릅니다.
   ```bash
   python3 -I .claude/skills/portfolio-image-crop/measure.py bbox src/<폴더>/_raw/a.png "r>235 and g>235 and b>235" 400,300,1500,700
   python3 -I .claude/skills/portfolio-image-crop/crop.py src/<폴더>/_raw/a.png src/<폴더>/images/b.png center 955 515 720
   ```
3. 만든 크롭을 **모두 직접 봅니다**(Read). 가장자리 조각·잘린 글자·빈 여백이 있으면 고쳐서 다시 자릅니다(사용자에게 보여 주기 전에).
4. `_raw/crops.json`에 기록합니다: `{ "<크롭 파일 이름>": { "src": "<원본 이름>", "box": [x, y, w, h], "section": "<넣을 절 제목>", "alt": "<설명>" } }`.

## 3. 보여 주고 요청 받기

1. 크롭 파일을 `SendUserFile`로 보냅니다(`display: "render"`, 캡션에 번호 순서).
2. 번호 표를 보여 줍니다.

   | 번호 | 파일 | 원본 | 넣을 절 | 남긴 부분 | 크기 |
   |---|---|---|---|---|---|

3. "고칠 번호와 요청을 알려 주세요(예: 3번 글자 가운데로, 7번 두 캐릭터 중점이 가운데·더 넓게). 괜찮으면 '반영해 줘'"라고 묻고 기다립니다.
4. 요청을 받으면 그 번호만 다시 자르고(필요하면 `measure.py`로 재서), 직접 본 뒤, **바뀐 것만** 다시 보내고 표에 무엇을 어떻게 바꿨는지 적습니다.
   요청끼리 부딪히면(예: 정확히 가운데 vs 아래 UI까지 담기) 하나를 고르고 무엇을 양보했는지 숫자로 말합니다(예: "골렘이 세로 중앙보다 3% 위").
5. 사용자가 "반영해 줘"라고 할 때까지 3~4를 반복합니다.

## 4. 반영 (확인받은 뒤에만)

1. **기술 문서**: 정한 절에 `![<설명>](images/<파일>)` 줄을 넣거나(앞뒤 빈 줄, 표 밖), 같은 장면을 가리키던 예전 경로를 새 파일로 바꿉니다. 그 밖의 글은 고치지 않습니다.
2. **data**(`data/projects/<폴더>.json`이 있을 때):
   - 경로를 바꾼 그림: JSON 안의 모든 같은 `src`(그리고 `cover`·`coverLogo`)를 새 파일로 바꾸고 `w`·`h`를 새 크기로 맞춥니다.
   - 새로 넣은 그림: data를 손으로 만들지 말고 `/portfolio-build <폴더>`를 다시 실행하자고 안내합니다(기능 화면·발표 덱 장면은 빌드가 정함). 실행은 사용자가 원할 때.
   - 그다음 `python3 .claude/skills/portfolio-build/deck-edits.py apply --all`.
3. **확인**(미리보기 서버 `portfolio`, 브라우저 캐시를 피하려고 바뀐 파일은 `fetch(u, {cache:'reload'})` 뒤 새로고침):
   - 포트폴리오 문서: `PFPage.report()`의 `images.broken`이 비어 있고, `fit`(4:3과 많이 달라 여백을 둔 그림)에 크롭이 없음.
   - 발표 덱 `project.html?p=<폴더>`: `PFScene.report().audit`이 0건. 장면 수가 바뀌었으면 왜 바뀌었는지 확인(예: 대표 이미지가 커져 옆 표가 나뉨 → 표를 따로 장면으로).
   - 상세 문서 `doc.html?p=<폴더>`: 그림이 모두 열림.
4. `_raw/`의 원본은 그대로 둡니다. 원본이 아직 `images/`에 남아 있고 문서·data 어디에서도 쓰이지 않으면 `_raw/`로 옮길지 묻습니다.
