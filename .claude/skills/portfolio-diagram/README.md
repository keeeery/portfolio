# /portfolio-diagram — 다이어그램 배치 다듬기 스킬 사용 안내

> 저처럼 다이어그램 배치가, 연결선이 꼬이는 게 거슬려서 **고쳐야만 하겠다** 하는 변태들?을 위한 스킬입니다.

기술 문서의 Mermaid 그림은 Mermaid가 칸 자리를 알아서 정해서, 그림이 조금만 복잡해져도 이런 일이 생깁니다.
- 선이 그림 바깥을 크게 돌아감
- 화살표끼리 엇갈림
- ㄹ자로 두 번 꺾임
- 선 글자가 칸에 딱 붙음
- 묶음 폭이 제각각

이 스킬은 정해 둔 규칙으로 그림을 다시 배치합니다. 그런 다음 **실제 페이지에서 겹침을 재고, 전후 비교 이미지**를 보여 줍니다.
mac·Windows 모두에서 동작합니다.

---

## 1. 무엇을 해 주나

- **훑기**: 내 기술 문서의 그림을 모두 읽고, 고치면 좋을 그림을 우선순위 목록으로 보여 줍니다. 고치는 건 내가 고른 것만 합니다.
- **한 그림 다듬기**: 스크린샷이나 "Arcanist 3.3 그림"처럼 지목하면 그 그림만 다듬습니다.
  - 한 방향으로 읽히는 줄기를 만듭니다.
  - 격자로 배치합니다.
  - 되돌아가는 선은 하나만, 바깥으로 돌립니다.
  - 그 밖의 배치 규칙은 아래 3절에 있습니다.
- **직각 화살표 엔진**: 화살표를 수직·수평 직선 + 둥근 모서리로 다시 그립니다. 원문에 `%%` 주석 줄을 적어 배치를 고를 수 있습니다.
- **재고 보여 주기**: 다듬을 때마다 이것을 확인해서 보여 줍니다.
  - 칸끼리, 칸과 선 글자, 선 글자끼리 겹치는 곳(0건이어야 함)
  - 선 글자가 칸에 6px 안으로 붙은 곳
  - 그림이 페이지에서 얼마나 줄어 보이는지
  - 전후 비교 이미지
- **발표 덱 확인**: 덱에도 쓰이는 그림이면 덱의 배치 점검(빨간 띠)도 봅니다.

## 2. 원문에 적는 문법 (Mermaid가 무시하는 주석이라 엔진이 없어도 그림은 그려짐)

```
%% 격자: Input Player Hit Tracker | - - Resolver - | - Entity Combat Observer
%% 화살표 Discard -> Draw: 나감=오른쪽 들어감=오른쪽 거리=84
%% 화살표: 곡선
```

| 줄 | 뜻 |
|---|---|
| `%% 격자: A B \| C D` | 칸을 바둑판처럼 배치. 줄은 `\|`, 빈자리는 `-`, 이름은 원문 id(상태 그림 시작 점 `root_start`, 끝 점 `root_end`). 한 줄에 같은 이름을 이어 적으면(`P P P`) 그 칸이 여러 열에 걸쳐 길게 놓임 |
| `%% 화살표 X -> Y: 나감=… 들어감=… 거리=N` | 화살표 하나가 나가고 들어갈 변(위/아래/왼쪽/오른쪽), 바깥으로 돌 때 칸에서 떨어질 거리 |
| `%% 화살표 X -> Y: 곡선` · `%% 화살표: 곡선` | 그 화살표만, 또는 그림 전체를 Mermaid 곡선 그대로 |
| `note for X "글<br>글"` (classDiagram) | 칸 바로 위에 붙는 역할 메모(표 대신) |
| `subgraph G["<div style=width:705px>이름"]` | 묶음 폭 맞추기(좁은 묶음을 넓힘) |
| `state "<div style=width:367px>Idle</div>" as Idle` | 칸을 넓혀 아래 여러 칸으로 수직 화살표 |

엔진이 알아서 하는 것:
- 겹치는 폭이 있으면 한 줄 직선을 먼저 씁니다.
- 오가는 화살표 두 개는 나란한 두 줄로 그립니다.
- 같은 변에서 엇갈리는 화살표는 붙는 자리를 맞바꿉니다.
- **같은 변 한 점에 몰린 화살표는 자리를 나눕니다.**
- 선 글자가 칸과 겹치면 다른 자리로 옮깁니다.

## 3. 지키는 규칙 (요약)

| 규칙 | 내용 |
|---|---|
| 한 방향으로 | 화살표는 위→아래(같은 줄은 왼→오른). 거꾸로 가는 선은 되돌이 하나만, 바깥으로 |
| 꺾임은 한 번까지 | ㄹ자가 생기면 받는 칸을 보내는 칸 바로 아래로 |
| 격자는 방향이 안 깨질 때만 | 칸이 많고 순환이 있으면 층(위→아래)을 먼저 |
| 칸 이름 | 흐름 그림은 한국어 동작, 구조 그림은 클래스명. 코드에 없는 상태 이름은 한국어로 |
| 판단 칸 | 문장으로 묻기("~할 수 있는가"), 갈래는 예/아니오 |
| 시작·끝 점 | "처음 상태가 이 그림의 주제인가?" — 주제면 칸으로(점 없음), 주제 밖이면 점으로 |
| 설명 문장 | 그림 바로 아래 "이 다이어그램은 ~ 도식화한 것입니다." |
| 지어내지 않기 | 칸·글자·메모는 기술 문서에 있는 사실만. 칸을 빼거나 문장을 바꾸는 건 확인받고 |
| 묶음 모양 | 스타일 없이 Mermaid 기본. 데이터 원기둥 칸은 합치지 않음 |
| 렌더러·커밋 | 엔진을 고치는 건 확인받고, 고친 뒤 모든 그림 전후 비교. 커밋은 요청할 때만 |

자세한 규칙은 `SKILL.md`에 있습니다.

## 5. 설치 (내 포트폴리오 레포에 넣기)

필요한 것은 **두 군데**입니다.
- 스킬 폴더 `.claude/skills/portfolio-diagram/`
- 엔진 `assets/diagram-tidy.js`

### 방법 A — 공유한 사람의 레포에서 git으로 받기 (추천)

```bash
git remote add diagramskill https://github.com/keeeery/portfolio.git
```

```bash
git fetch diagramskill main
```

```bash
git checkout diagramskill/main -- .claude/skills/portfolio-diagram assets/diagram-tidy.js
```

```bash
git remote remove diagramskill
```

- 다른 파일(내 `index.html`·`data/`·`src/` 등)은 건드리지 않습니다.
- 주소는 이 스킬을 공유한 사람의 레포입니다. 다른 사람에게서 받았다면 그 주소로 바꿉니다.

### 방법 B — 압축 파일로 받기

내 레포 맨 위에 풀어 아래 두 곳이 생기면 됩니다.

```
내 레포/
├── .claude/skills/portfolio-diagram/   (SKILL.md · diagram-tool.py · README.md)
└── assets/diagram-tidy.js
```

> `.claude` 폴더는 숨김 폴더입니다(mac: Finder에서 ⌘+Shift+. / Windows: 탐색기 [보기] → [숨긴 항목]).

### 설치 뒤 — 엔진 연결 (처음 한 번)

Claude Code를 다시 열고 아래를 입력합니다.

```
/portfolio-diagram 준비
```

Claude가 내 렌더러에 엔진을 연결합니다. 고칠 곳을 **보여 주고 확인받은 뒤** 고칩니다.
- `doc.html`·`project.html`에 `<script>` 한 줄
- `assets/doc.js`·`assets/project-deck.js`에 엔진을 부르는 줄
- Mermaid 버전(11.12.0 이상)

연결하지 않아도 원문의 `%%` 줄은 주석이라, 그림은 Mermaid 기본 모양으로 그대로 그려집니다.

> **`/portfolio-update` 주의:** 템플릿 업데이트는 `doc.html`·`project.html`·`assets/`·스킬 폴더를 원본으로 바꿉니다. 그래서 엔진과 이 스킬이 빠질 수 있습니다.
> 업데이트 뒤 그림이 곡선으로 돌아가거나 `/portfolio-diagram`이 안 보이면, 설치와 `준비`를 한 번 더 하세요.
> 원문에 적은 `%%` 줄은 기술 문서에 있으니 그대로 남습니다.

## 6. 사용 방법

| 입력 | 범위 | 하는 일 |
|---|---|---|
| `/portfolio-diagram 전체` | 모든 프로젝트의 모든 그림 | 프로젝트·문서 순서대로 다듬기 |
| `/portfolio-diagram 2-Folk-Sack` | 한 프로젝트의 모든 그림 | 그 기술 문서의 그림을 차례로 다듬기 |
| `/portfolio-diagram 2-Folk-Sack 4.1` · `… 5번` · 스크린샷 + "이것도 다듬어 줘" | 그림 하나 | 그 그림만 다듬기 |
| `/portfolio-diagram` · `/portfolio-diagram 훑기 [폴더]` | 보기만 | 개선 후보 목록만 |
| `/portfolio-diagram 준비` | — | 엔진 연결(처음 한 번) |

여러 그림을 한 번에 할 때 이렇게 나눠서 처리합니다.
- **배치만 바꾸는 것**(`%%` 줄·줄바꿈·폭·순서)은 바로 합니다.
- **내용이 달라지는 것**(칸 이름 바꾸기·칸 빼기·선 글자 줄이기·설명 문장)은 「확인할 것」 목록에 모아 맨 끝에 한꺼번에 묻습니다.
- 이미 규칙에 맞는 그림은 그대로 둡니다.

### 정보가 부족하면

그림을 그리는 데 필요한 관계(누가 누구를 부르는지 등)가 기술 문서에 없으면, 지어내지 않고 아래 순서로 찾습니다.
1. 이 레포의 `src/<폴더>/code/`·`_intake/`
2. **같은 PC에 받아 둔 원본 저장소**: 문서의 GitHub 주소와 원격 주소가 같거나, 문서가 말한 소스 파일(`HitBox.cs` 등)이 많이 들어 있는 저장소. 포크·이름 변경으로 주소가 달라도 찾습니다. 읽기만 합니다.
3. **원격 저장소**: 같은 PC에 없으면 문서의 GitHub 주소에서 임시 폴더로 받아 읽습니다. 비공개면 `gh` 로그인이 필요합니다.
4. 그래도 없으면 어쩔 수 없음: 그 부분은 비워 두고 "근거를 찾지 못함"으로 알립니다.

코드에서 찾은 내용을 그림에 넣는 건 기술 문서 내용이 늘어나는 일입니다. 그래서 근거(파일·줄)를 보여 주고 확인받은 뒤에만 넣습니다.

말로 해도 됩니다.
- "이 그림 화살표가 ㄹ자로 꺾였는데 고칠 수 없나"
- "빈 공간 확인 화살표가 좀 더 오른쪽으로 갔으면"
- "두 묶음 너비 똑같이 맞춰 줘"
- "세로 배치가 낫겠다"
- "맨 위 점은 없애도 될 듯"

결과는 매번 이렇게 받습니다.
- 바꾼 `%%` 줄
- 겹침 0건 확인
- 크기 변화
- 전후 비교 이미지
- 발표 덱 상태

그림을 다른 절로 옮기는 등 원문 구조가 바뀌면, 발표 덱에 빨간 띠가 생길 수 있습니다. 이때는 `/portfolio-build <폴더>`로 다시 만들면 됩니다. 커밋은 하지 않습니다.

> **에디터에서 같은 기술 문서를 열어 두셨다면** 저장하기 전에 다시 불러오세요. 예전 내용으로 저장되면 Claude가 고친 배치가 사라집니다.

## 7. 도구 직접 쓰기 (선택)

```bash
python3 .claude/skills/portfolio-diagram/diagram-tool.py measure 2-Folk-Sack "매몰 대기" --save before.svg
```

```bash
python3 .claude/skills/portfolio-diagram/diagram-tool.py compare before.svg after.svg compare.png
```

```bash
python3 .claude/skills/portfolio-diagram/diagram-tool.py audit 2-Folk-Sack
```

| 명령 | 하는 일 |
|---|---|
| `measure <폴더> <표시 글자>` | 그 글자가 든 그림의 크기·칸·선 글자·겹침. 표시 글자는 그 그림에만 있는 칸 글자 |
| `compare <전.svg> <후.svg> <결과.png>` | 전후 비교 이미지(`--vertical` 위아래로 · `--light` 흰 바탕) |
| `audit <폴더>` | 발표 덱 배치 점검 |
| `snapshot <이름>` · `diffsnap <이름1> <이름2>` | 엔진을 고치기 전후로 모든 그림의 선 모양을 비교 |
| `list [폴더]` | 기술 문서마다 그림 목록(번호·줄·절·종류) |
| `findrepo <폴더>` | 원본 코드가 이 PC 어디에 있는지(원격 주소·소스 파일 이름으로) |
| `fetchrepo <GitHub 주소>` | 원격 저장소를 임시 폴더에 얕게 받기 |
| `env` | 찾은 Chrome·파이썬·엔진 파일 |

## 8. 문제 해결

| 증상 | 할 일 |
|---|---|
| "Chrome을 찾지 못했습니다" | Chrome을 설치하거나 `--chrome "<경로>"` |
| `measure`에서 `engine: false` | `/portfolio-diagram 준비`로 엔진 연결 |
| 그림이 그대로 곡선 | 브라우저 캐시 — 새로고침(Ctrl+Shift+R). 또는 업데이트로 엔진이 빠졌는지 확인 |
| "표시 글자가 들어 있는 그림이 없습니다" | 그 그림에만 있는 다른 칸 글자로(선 글자·`<br>` 사이 글자는 피함) |
| 고친 배치가 사라짐 | 에디터가 예전 내용으로 저장한 것 — 에디터에서 파일을 다시 불러온 뒤 "다시 적용해 줘" |
| 발표 덱에 빨간 띠 | 원문이 바뀐 것 — `/portfolio-build <폴더>` |

## 9. 이 스킬을 다시 공유하려면

- 내 레포에 두 곳(`.claude/skills/portfolio-diagram/`, `assets/diagram-tidy.js`)이 커밋·푸시돼 있으면, 다른 사람은 설치 방법 A의 주소만 내 레포로 바꿔 받으면 됩니다.
- 렌더러에 엔진을 연결한 줄(`doc.html`·`doc.js` 등)은 사람마다 렌더러가 달라서 공유하지 않습니다. 받는 사람이 `준비`로 자기 렌더러에 맞춰 넣습니다.
- 모두가 `/portfolio-update`로 받게 하려면 템플릿 원본 레포에 제안(Pull Request)하는 방법도 있습니다(강사님 확인 필요).
